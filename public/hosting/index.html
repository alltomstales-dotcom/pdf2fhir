Disclaimer: Not clinical advice. Not for diagnosis, treatment, or billing. Prices are approximate us-east-1 on-demand ballparks (API list / EC2 OD); verify before you buy. This page is a SIM / educational planning aid for PDF2FHIR demos and FDE conversations.
Rule of thumb: Under ~500 docs/day, managed mini / Haiku usually wins on total cost + ops. Bedrock ≈ Anthropic quality with AWS account packaging (BAA path) — typically not cheaper than going direct to Anthropic. Prefer Spark / g6e (or larger) when you need air-gap or PHI that must stay on-prem / in-VPC with no third-party model API.

Architecture reminder

PDF2FHIR (and production-shaped cousins) should not ask the LLM for a free-form FHIR Bundle. Keep the model in a typed extract lane; map and validate deterministically.

PDF / text → LLM → typed JSON extract (schema-constrained) → deterministic FHIR R4 mapper → terminology / code post-check → Bundle (Patient, Encounter, Condition, Observation, MedicationRequest, …)

1. Managed API

OpenAI gpt-4o-mini / Azure OpenAI

  • Cheapest “good enough” extract for structured clinical JSON at demo and pilot scale.
  • Azure OpenAI when the customer already has an Azure enterprise agreement / HIPAA BAA path.
  • ~$ / doc ≈ 8e-3×$0.15 + 2e-3×$0.60 ≈ $0.0024 (list ballpark).

Anthropic Claude (Haiku / Sonnet)

  • Haiku: strong structured extract; often the quality step-up still under a few cents/doc.
  • Sonnet: use when long messy notes need better instruction-following; watch $/doc (~5–6¢ at 8k+2k).

AWS Bedrock (Claude Haiku/Sonnet, Llama)

  • Same model families, billed through AWS — packaging and BAA/compliance story for AWS-native accounts.
  • Expect Anthropic-like quality, not a discount vs Anthropic direct. Llama on Bedrock can be the cost lever if quality gates pass.
  • Wins when the FDE motion is “stay inside the customer’s AWS org,” not when pure $/1M is the only criterion.

2. Hosted open-weight (OpenAI-compatible)

  • Fireworks / Together / Groq-style endpoints for Qwen / Llama — point PDF2FHIR Settings base URL at their /v1 and keep the same client.
  • Often competitive with mini on $/doc for mid-size models; latency varies (Groq-class for speed demos).
  • Still SaaS: confirm DPA/BAA and residency before PHI. Great for public demos and de-identified corpora.

3. Self-host EC2 (us-east-1 OD ballparks)

Instance GPU ~$ / hr Practical model class Notes for extract
g4dn T4 16GB ~$0.53 ~7B Entry GPU; fine for small instruct models + batch extract if quantized.
g6 L4 24GB ~$0.80 ~14B Better headroom; common sweet spot for always-on VPC extract.
g6e L40S 48GB ~$1.86 ~32B Stronger quality without jumping to H100; air-gap-ish inside VPC.
p5 H100 80GB ~$6.88 70B+ Only when 70B quality is required and utilization is high; otherwise managed Sonnet is cheaper.
  • Utilization is the whole game. A g6 at $0.80/hr idle 20 hrs/day loses badly to mini at $0.003/doc.
  • Estimate docs/hr from tokens/sec of your serving stack (vLLM etc.), then $/doc ≈ $/hr ÷ docs/hr.
  • Add autoscaling, spot (careful with stateful loads), and private networking to the design — not just the GPU SKU.

4. On-prem DGX Spark

  • 128GB UMA class workstation / appliance: room for Qwen2.5-72B-class (quantized / efficient serving) without sending tokens to a vendor API.
  • PHI stays local — the clearest win vs any managed or hosted-open-weight option when policy is air-gap or “data never leaves the building.”
  • Trade CapEx + operator time for zero marginal API spend; pair with the same typed-JSON → FHIR mapper so the LLM never invents Bundle resources.
  • Also a strong live-demo story: extract on the desk, Bundle on the laptop, no egress.

PDF2FHIR demo Settings already speak OpenAI-compatible chat/completions — so managed OpenAI/Azure, many Bedrock-compatible proxies, and Fireworks/Together/Groq-style hosts can be swapped via base URL + model without rewriting the mapper.
Prices and SKUs change. Re-check OpenAI / Anthropic / Bedrock model cards and EC2 pricing in the target region before a customer quote. Token counts above are planning defaults for ~8k in + ~2k out JSON, not a guarantee.
